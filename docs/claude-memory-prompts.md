## 召回时机

完整版的 `When to access memories` 明确规定：

1. 记忆与任务看起来相关，或者用户提及过去会话中的工作时，访问记忆。
2. 用户明确要求检查、回忆或记住时，**必须访问记忆**。这一条属于记忆上下文中的要求，不应解释成任何“检查代码”任务都无条件召回全部记忆。
3. 用户说忽略或不使用记忆时，不应用、引用、比较或提及记忆内容。
4. 把记忆视为过去某时刻的背景。以它回答问题或建立假设前，核对当前文件、资源等事实；冲突时相信现在的观察，而不是旧记忆。
5. 推荐具体文件前检查它存在；推荐函数或 flag 前搜索确认。如果用户将据此行动，先验证再推荐。当前状态优先读代码、Git，而不是拿旧架构或活动摘要作结论。

正常索引模式由模型按相关性选择主题文件读取，并非无条件加载全部正文。此次探测只覆盖普通文件记忆，不将其它灰度预取或 connected-store 分支混入这个结论。

## 写入时机

完整版既要求长期积累记忆，也明确列出四种类型的主动触发条件。它不是只在用户说“记住”时才允许保存。

| 类型 | 原生主动触发条件 | 保存的重点 |
|---|---|---|
| user | 学到用户角色、偏好、职责或知识背景时 | 未来如何协作和解释问题；不记录负面人格判断或无关信息 |
| feedback | 用户纠正做法，或确认一个非显然的做法有效时 | 同时从失败和成功学习；保留原因，不只存禁止事项 |
| project | 学到谁在做什么、为什么、截至何时时 | 代码或 Git 无法提供的工作背景、约束和决策；相对日期转为绝对日期 |
| reference | 学到外部资源及其用途时 | 以后到哪里查询最新信息，而不是复制一份会过时的资料 |

用户明确要求记住时，立即选择合适类型保存。feedback 与 project 正文分别以规则或事实开头，再写 Why 和 How to apply。精简版保留了类型、查重、更新、日期和质量约束，但没有完整列出上述 `when_to_save` 段落。

### 不应保存的内容

原生明确排除：代码能提供的结构和约定、Git 历史、已在 CLAUDE.md 中的内容、具体调试修复配方、临时进度、当前会话状态。**用户要求记住也不取消这些排除项**；应澄清真正非显然、能跨会话改变行为的经验，而不是保存流水账。

## 删除时机

原生有两类删除条件，不能只整理成“用户说忘记”：

- 用户要求忘记：找到并移除相关条目。
- 记忆被证实错误或过期：完整版要求更新或移除；精简版明确要求删除被证实错误的记忆。对于仍有可保留内容的记录，应先考虑修正，不推导出“过期就一律删”。

原生正文文件和 MEMORY.md 指针由模型维护；cc-webui 中应由 `memory.delete` 统一清理正文版本和索引。是否允许未获用户明确请求的删除，是产品策略差异，应明确决定，不能一边保留原生触发规则、一边让工具说明要求只能按用户请求删除。

## 更新时机

原生要求：

1. 每次保存前先找是否已有覆盖同一主题的记忆；能更新就不新建重复条目。
2. 事实变化、错误、过期或与当前观察冲突时，更新或移除旧记录。
3. 正文变化时，name、description、type 也要与内容保持一致。
4. project 状态变化较快，维护谁在做什么、为什么、何时等理解；按主题组织，不按时间堆日志。

cc-webui 的 revision CAS、幂等 ID、写入成功后才宣称完成，是 MCP 存储适配新增的协议规则，可以保留，不属于要从原生照搬的文件写法。

## 与旧 v1 模板的差异及 v2 修正

下表记录提取时的 v1 差异。现实现为 [server/project-memory/prompt.ts](../server/project-memory/prompt.ts) 的 v2；[memory MCP 工具说明](../server/mcp-memory-route.ts)也同步表达主动保存和经证据确认的清理。运行时不会导入本目录的原生提示。

| 规则 | 旧 v1 状态 | v2 修正或保留 |
|---|---|---|
| 相关任务、过去工作时召回 | 核心已表达 | 已补齐明确检查、回忆、记住的强制召回，明确 opt-out 时不引用、比较、提及正文或自动维护 |
| 四类型主动保存 | 类型有定义，触发不足 | 已列出角色学习、纠正、正向确认、工作约束、外部资源等触发，不等待“记住”口令 |
| 用户要求记住或忘记 | 已表达 | 保留适合长期记忆的前提和工具成功后才能宣称完成 |
| 错误或过期记忆的删除 | 不完整 | 已允许当前证据确认后的更新或删除；优先保留并修正有用内容，不按年龄、索引省略或最近没用删除 |
| 查重后更新而不重复创建 | 已表达 | 保留 read、expected_revision 和冲突后重读 |
| 使用前核对旧事实 | 大部分已表达 | 已明确当前证据优先，按冲突修正或移除，旧 tool result 不是永久缓存 |
| 相对日期转绝对日期 | 未表达 | 已补齐会话日期/时区下的绝对日期，歧义先澄清 |
| 不保存代码、Git、项目文档、临时进度 | 已表达主要原则 | 已单列调试修复配方及显式要求也不取消排除项 |
| 一主题、Why、How to apply、关联链接 | 已表达 | 保留既有结构 |
| 文件工具写入与手工更新索引 | 有意替换 | 不照搬 Write 或 MEMORY.md 两步写法，继续用原子 memory.save |
| 私有与团队记忆 | 有意不同 | 用户已确认项目共用 namespace，不能照抄其它分支而按账号重新分库 |

v2 的 reviewed fixture 位于 `server/project-memory/fixtures/`。规则契约测试对照原生默认提示并锁定逐字模板；假 CLI 集成测试确认 Claude/Codex 收到相同 writable/readonly 规则、下一轮索引刷新、原生关闭及功能关闭后恢复。MCP 测试确认新工具说明和 Plan 仍拒绝 save/delete。上述验证不保证模型百分之百遵守，真实模型的召回质量和写入选择仍是独立验收项。

## 重现方法

从仓库根运行，输出目录每次用新的私有目录，避免覆盖旧研究：

```bash
OUT="$HOME/.cc-webui/research/claude-memory/new-research-directory"
python3 scripts/research/extract-claude-bun.py "$(command -v claude)" "$OUT"
python3 scripts/research/probe-claude-memory.py "$(command -v claude)" "$OUT/probe"
python3 scripts/research/verify-claude-memory-probe.py "$OUT/probe" "$OUT/fixtures"
```

提取器只读二进制，并对 Mach-O 段和 Bun 指针做边界检查；未知布局直接失败。上述校验器以本次 2.1.283 的两模型六用例为基线，新版本需要重新确认布局、规则和结果，不能沿用旧结论。
